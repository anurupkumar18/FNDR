## Recent Development

Latest work on the Beta-to-Final push:

- **Notch Do has its own hands (2026-10-08, ADR 026 item 4, first slice):** `fndr operator-mcp` is a small stdio MCP server inside the FNDR binary with the tool names `operator/policy.rs` already classifies: `get_app_state`, `click`, `set_value`, `type_text`, `press_key`, `scroll`, `list_apps`. A click is AXPress on the element FNDR printed, never a screen position; an element index is valid only for the tree it came from (indexes keep counting up, any action drops the tree, and an element that no longer reads as printed is refused); FNDR, blocklisted apps and password fields are refused; no screenshots; it exits when Codex closes the pipe or goes away. `detect_backend` now prefers it, so "Operate my Mac" no longer reports "nothing to click and type with" on a Mac that has no helper; open-computer-use and the old bundled launcher stay as fallbacks until the twenty-task set passes. Checked by 12 unit tests and 4 key-script tests with a fake desktop, one test that runs the real binary over a pipe, and by hand on Calculator through the real Accessibility API (press, key, paste, stale index refused, FNDR refused). **Not yet verified: a full Codex session through it, the twenty-task set, the fixture pages in a browser, or scrolling beyond page keys.**
- **Notch Do talks back (2026-10-08, ADR 020 amendment):** it says what it understood, each step as it starts, anything it asks first or leaves out, and the end, including how many steps FNDR checked itself and which are only as the model reported. On by default for Notch Do only, with a mute switch in the notch; Screen Guide and the rest stay silent unless opted in. It uses the Mac's own voices inside FNDR, so nothing leaves the Mac and nothing is left running; Stop, a new request, mute or closing the notch silences it at once. An ask-first step is announced aloud and still waits for a tap on Allow; a spoken "no" declines, a spoken "yes" approves nothing. The notch drops what it hears of its own voice. Not heard through real speakers yet; a spoken yes and a Settings switch are follow-ups.
- **The output quality lane checks itself (2026-10-08):** `make qa-vault` scores a copy of the owner's vault against written thresholds (12 checks: narration, placeholders, zero vectors, unrelated queries marked strong, labels outside the list, title and gist search, voice) and says PASS or FAIL. `make test-clean FILES=...` runs the library tests on the committed tree plus only the named files, so another session's unfinished work cannot break them. The retrieval gate refuses a profile seeded on an earlier day. The Python script tests, 112 of them that nothing ran, are part of `make test` and CI. `AGENTS.md` carries the gates and what the lane measured about the on-device model: it extracts, it does not synthesize, and a claim is kept only with evidence from the capture.
- **A Vault session row describes the session (2026-10-08, VS-92):** it shows how long the session ran, the files, decisions, next steps and errors its moments record, the most detailed earlier sentence, and links to sessions in other apps that share a file or two distinctive title words within ten minutes. It is composed from the moments on read; no model writes it and nothing is stored.
- **Search and labels need evidence (2026-10-08):** a time phrase no longer makes an unrelated result a confident match (9 of 24 time-phrased no-match queries were marked strong; now 1). The label `reviewing_agent_output` stays only when an assistant is on screen. A card line that only repeats the window title reads "Viewed {title}.". The second summary repair is applied to the owner's vault (62 of 158 rows).
- **Agent leftovers removed (2026-10-08):** eight backend commands that only the deleted Agent and Research panels called are gone, with their front-end wrappers and the legacy `agent_runner.py` sidecar: starting, polling and stopping a Python agent task, direct Ollama chat, one-click Ollama setup, and manual gateway start, stop and sync. Nothing on screen changes; the gateway still starts and stops by itself.
- **The repo checks itself for rot (2026-10-08):** two tests now run with `npm test`. One fails when the front end calls a backend command that is not registered, when a backend command has no caller, or when a wrapper has no importer; the 3 uncalled commands and 51 unused wrappers that exist today are recorded in a list that may only shrink. The other fails when a file people are told to read first points at something that is gone. `AGENTS.md` gains the shared-checkout and shipping rules, and asks every claim to say whether it was checked by a unit test, a fake, or the real thing. Notch Do's planner is now told which app is in front, so "this page" means something, and a request that only reads shows what was reported.
- **Notch Do runs live, and what that showed (2026-10-08):** with open-computer-use installed, Notch Do typed into a search box, asked before Add to cart, left buying out, did not type into a password field, ignored an instruction planted in an article, and pressed the right button on a page whose buttons move. Getting there fixed two faults that stopped every run: FNDR switched off a Codex feature the installed Codex no longer has, which also silently broke Screen Guide's ChatGPT answers, and turns ran on a model the plan did not include. Also fixed: one no now covers the rest of a step (the model had gone on to ask five more times by other routes), a finished run says what it left out, and Privacy Activity counts the picture of the app's window that the helper sends with each read. Evidence: `docs/evidence/W03/agent-surfaces-phase1.md`.
- **Three decisions closed (2026-10-08):** ADR-018 is accepted with one rule: a cloud model is used only on a turn the person starts, on a surface where they chose the provider; nothing FNDR does in the background ever goes to one. ADR 026: Notch Do will act with FNDR's own accessibility code for Final, because the ChatGPT app's current Computer Use is a single run-any-code tool FNDR cannot check action by action; until then Notch Do runs only where open-computer-use is installed. With nothing to act with, "Operate my Mac" cannot be turned on and says why, and the notch does not offer Do. Agent chat history keeps the newest 200 chats and 400 messages in each, and nothing expires by age.
- **Agent docs match the product (2026-10-08):** `docs/agent.md` now describes the Hermes chat page (providers, what is sent, every command the page calls) and keeps the model-free MCP `agent.*` runner as its own section. The Screen Guide PRD covers Point with OpenClicky and says the Operate my Mac switch belongs to Notch Do. The briefing and greeting commands moved out of `hermes_agent.rs` into `ipc/commands/home.rs`, with no change in behavior.
- **Agent and Notch Do, easier to use and to trust (2026-10-07):** Hermes answers show lists, code, emphasis and links, and a `[2]` in an answer opens the memory it cites; every memory in a message now has its own number. The notch shows what it heard for a moment before sending it, a finished run says how many steps FNDR checked itself and that nothing is undone automatically, and a request Notch Do never carries out (sending, deleting, buying, passwords) gets that reason instead of "nothing to do". "Operate my Mac" has its own setting, the sidebar has Trust and Labs groups, and Hermes's tool limit was confirmed at the pinned version and on a live gateway (one tool where the default is 31; with the default it wrote a file and ran a shell command unasked). An answer now says when Hermes searched memories on the way to it. A memory from an app excluded since it was picked is no longer sent with a message. Screen Guide answers on this Mac, and says so, when ChatGPT is chosen but cannot answer. Privacy lists recent Notch Do runs by what became of their actions (done, asked first, refused, failed).
- **Agent surfaces, decisions built (2026-10-07, ADR 024 accepted):** Hermes no longer gets a terminal, file writes, code execution, browser control or schedules, only a planning list and read-only memory search, and only FNDR's pinned Hermes runs. Memories FNDR finds on its own go to a cloud provider only when turned on in Agent setup, which now says what is sent and where; the chat shows every memory FNDR added. In Notch Do a spoken "yes" no longer approves anything, browsers ask before any click that is not a link, tab, search box or play control, a link opens unasked only when it is a search for words that were said or a site that was named, typing runs only while FNDR knows the search box has focus, Terminal and similar apps are refused, and a plan starts by itself only when no step can need a yes. The Hermes update button is gone, and Sign out says it signs Codex out on this Mac too.
- **Agent surfaces, first safety fixes (2026-10-07):** Notch Do no longer reads or acts while it is still planning, never reads or operates an app on the blocklist or FNDR itself, and stops at the next action when actions are switched off or Private Mode comes on. A spoken "please stop now" stops a run. Quitting FNDR ends the Hermes gateway and any Notch Do run. Screen Guide's ChatGPT answers now appear in Privacy Activity, the list survives a restart (30 days, 200 rows) and says when memories, on-screen text or a screenshot went along. Hermes's key and config files and the staged Screen Guide screenshot are readable by the owner only, and a leftover screenshot is removed at startup. The Agent header names the missing step instead of "Not set up", a failed send hands the message back, and the usage card says its limits cover the whole ChatGPT account. A run also ends within half a second when actions are switched off or Private Mode comes on mid-action. The Agent page has a Stop button that hands the message back, a failed send stays in the chat marked "Not sent", chat history is written by one writer to an owner-only file, a gateway that fails to start reports its last error line, and a gateway left running by a crash is stopped at the next start. Findings and evidence: `docs/evidence/W03/agent-surfaces-phase1.md`; plan: `docs/superpowers/plans/2026-10-07-agent-surfaces-work-breakdown.md`.
- **Summaries written without a model say only what they know (2026-10-07):** when the model is unavailable or its output is weakly grounded, the summary used to read "You were reviewing {a line of body text} on {app}", with the activity set to "reviewing" and an invented intent. It now reads "Viewed {title or files} in {app}", with the activity unknown and no intent. A leading "Reviewing" goes to the past tense on display, and sentences about the window or the OCR fall back to the title. On the owner vault 17 of 132 visible summaries opened with a past-tense verb; with the repair run on a copy, 50 do. **The repair is not applied to the real vault:** it lowers title search from 10 to 7 of 11, because stale second vectors that equal the title have been carrying title search (`docs/evidence/W04/voice-and-fallback.md`, `second-vector.md`).
- **Searching by a page's name works on purpose (2026-10-07):** ranking adds a fixed bonus when the query's words are a memory's window title. Title search had been carried by stale vectors; with them refreshed it found a memory of the searched page in the top five for 7 of 11 titles, and with the bonus for 10, with summary searches unchanged and the persona gate passing (`docs/evidence/W04/second-vector.md`).
- **Tasks stated outright are found without the model (2026-10-07):** on 30 labeled screens the model with the screen check got 29 right and a model-free finder 27; together 30, with no false tasks. Capture uses both.
- **The briefing is written without a model (2026-10-07):** three prompt versions were measured on the local 2B model. It invented advice ("a key takeaway for tomorrow..."), then copied its notes back word for word, then stated that an open task had already been submitted. The briefing in To-dos and the morning and evening notification now come from one function, `briefing::briefing_for`: up to three pieces of work in the order they happened, each told by its latest summary, then what is open. It says nothing when there is too little activity. The `daily_briefing` prompt and its cleanup code are removed.
- **Finished sentences, and a briefing that only reports (2026-10-07):** "The user has completed a repair of their database" was shown as "Has completed a repair of their database". The voice cleanup now gives "Completed a repair of the database", turns a leading "Reviewing" left by "is reviewing" into "Reviewed" for a list of known verbs, and drops "The session involves". A one-word window title ("FNDR" in a chat app) gives way to the sentence about the work in Resume. A capture that is mostly a macOS permission dialog is kept out of search and lists. `LLM_PROMPT_VERSION` is v7.
- **Daily Summary and briefing count only your own tasks (2026-10-07):** the summary's open-task list and count are the tasks a person added, accepted or took from a meeting, never unaccepted suggestions, and nothing is said when none are open. System processes such as UserNotificationCenter are no longer listed as apps used, and a bullet no longer repeats its topic as its example. The briefing looks back on today from noon (it used to be a morning briefing until 5 PM), reads only that window's activity plus up to three open tasks, and is skipped when fewer than three captures qualify (`briefing.rs`). The briefing prompt itself is unchanged and its output was not re-measured.
- **Tasks must be quoted from the screen (2026-10-07):** an audit of the owner's list found 471 open tasks from 147 memories, none ever completed, over half read off AI chat screens, and up to 33 from one memory because every merge asked again. Capture now asks once per new memory, never on AI chat or system screens, at most once per app per 10 minutes, and keeps a task only when the model quotes words that are on the screen and state a commitment or a request (`tasks/suggest.rs`). The quote is stored as the task's reason. A suggestion that means what a recent task already says (cosine 0.80 or more on the title) is not offered again. Opening To-dos no longer creates tasks from memories. To-dos now lists the person's own tasks first and offers at most five suggestions, each with its quote, for three days; a suggestion becomes a task only when accepted. Numbers in `docs/evidence/W04/task-audit.md`. Run on the real local model: across 28 synthetic screens it wrote 42 task lines, 12 screens state a task, and the check kept 11. At first sight of two unseen sets the check got 6 of 9 and then 7 of 8 screens right; each miss became a rule (a request counts only in mail, chat and notes; a deadline needs a date). On the owner vault the new pipeline makes no suggestions from the 147 memories the old one turned into 471 tasks; those 471 were dismissed with `retire_task_suggestions` on 2026-10-07. **Recall on real mail, chat and notes is not measured.**
- **Notch Do: voice-driven computer use (2026-10-06, `kunj-notch-computer-use`):** opening the notch in Do mode listens on FNDR's native on-device voice owner (the WebKit listener and spoken replies are gone). When speech ends, a Codex app-server turn on the person's ChatGPT plan plans the request; the plan card starts it after 1.5 s unless "stop" or Cancel. FNDR opens apps and links natively (NSWorkspace), hands only in-app UI to Computer Use (OpenAI's bundled plugin, else open-computer-use), checks every step itself (frontmost app, Spotify/Music playback, browser URL), retries once, and journals every action to `operator/journal.jsonl` with typed text hashed. Every computer-use call is gated in code (`operator/policy.rs`): reading, scrolling, media and search typing run; other typing and submits ask once; sending, deleting, buying, credentials, password managers and System Settings are refused. "Stop" kills the run and Codex's process group. ADR-020, ADR-022 and ADR-018 carry the 2026-10-06 amendments. Verified live from a shell harness (`live_notch_do_runs_the_example_request`, open-computer-use): "open Spotify, play Blinding Lights, then open the browser and look up looped transformers" finished in 135 s. **Not yet verified: voice inside the app**, and the bundled Computer Use, which needs FNDR to have Automation access to it.
- **Hermes on the same ChatGPT sign-in (2026-10-06):** no API key and no second login. Hermes imports the Codex login itself; the Codex app-server is the only refresher (before every Hermes start and every 30 minutes), and Hermes's copy is emptied whenever the login rotates. Live check: a Hermes call answered on the plan and `codex login status` still reported "Logged in using ChatGPT". FNDR installs a pinned Hermes (`b8880f1`, v0.18.2) into its app data on first run; the orphan `hermes-agent` gitlink is removed. The gateway restarts once after a crash and shows its state. Each Hermes message carries up to 5 memory snippets from the shared retrieve path instead of the old `FNDR_CONTEXT.md` snapshot, and Hermes can query FNDR over MCP.
- **Privacy Activity lists cloud model requests (2026-10-06):** feature, host and bytes FNDR sent for every Notch Do and Hermes request, never content.
- **One voice and honest insight fields (2026-10-06):** nothing FNDR writes about a memory has a narrator any more ("Reviewed the PR", not "You reviewed the PR"), including older stored text at display time. Vault insight rows no longer show activity identifiers, session ids, or next steps under "What changed".
- **One prompts file (2026-10-06):** every local-model prompt lives in `src-tauri/src/inference/prompts.rs` with guard tests; a prompt cannot change without a version bump. Unused model code (`vlm.rs`, `model_worker.rs`, `qwen_vl_memory.rs`) is gone. The v3 prompts are **not yet measured on the real model**.
- **Search query prompt (2026-10-06):** the live MiniLM route no longer prepends a BGE instruction to queries. Gate passes on all three seeded personas; numbers in `docs/evidence/W04/2026-10-06-query-prompt.md`. BGE prefixes are unchanged.
- **Vault filters and MCP start instructions (2026-10-06):** perspective filters no longer hide cards whose activity label is not the filter's own, and connecting agents are told where to start and that results are evidence, not instructions.
- **Agent approval gating** — `Act` mode now requires explicit approval before `OpenUrl` or `OpenFile`, closing a policy gap where those actions previously executed without a prompt.
- **Screen Guide observability** — every voice/ask stage transition is now logged, and the flow recovers cleanly from a stuck transcription or ask call.
- **MCP tool surface audit (RET-02)** — all 51 MCP tools classified by risk and overlap in `docs/product/mcp-tool-audit.md`, with keep/merge/remove verdicts (see below).
- **Capture enrichment scheduling policy (MEM-06)** — policy code merged but **not yet wired into the live pipeline**.
- **Eval gold set v0 (MOD-04)** — draft evaluation set added for review, not yet finalized.
- Trust and honesty pass across Search, Ask, Timeline, Memory Vault, Daily Summary, and Stats: clearer pending/error/stale states and consumer-honest labeling.
