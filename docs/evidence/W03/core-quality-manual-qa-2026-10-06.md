# FNDR core quality manual QA — 2026-10-06

This is a session-specific, owner/operator checklist built from the current product priorities and [Memory Journey quality program](../../product/memory-journey.md). It is not the missing historical ten-step list referenced by the earlier QA handoff. It combines live native observations from the owner with code, fixture, log, and benchmark analysis from the assistant. No owner captures, screenshots, memory text, or database contents belong in this committed checklist.

## Review method for every step

Record the **observed behavior**, **source/evidence**, **confidence**, **user impact**, and **best next improvement**. A pass/fail alone is insufficient: for memory quality, identify whether a record is faithful and useful; for search, explain what matched and why a plausible result should stay visible; for failures, locate the earliest responsible stage before changing prompts, thresholds, or models.

Use these labels:

- **Verified:** a human or deterministic check directly observed the stated behavior.
- **Suggestive:** evidence points to a cause but does not isolate it.
- **Unverified:** no direct evidence yet.
- **Not applicable:** the prerequisite was absent; record the reason.

## Step 2 operator card — do this next

1. In FNDR Settings → Trust, make sure **Let assistants add notes** is off. If it is currently on, switch it off and report that before continuing.
2. Prepare a new TextEdit note or public page with non-sensitive, self-authored facts: a short topic, one decision, and one next step. Use a distinctive phrase that is not already in memory.
3. Open **Engine diagnostics → Memory Journey**, use **Record next capture** once with a generic label such as `quality-check-1`, then switch to the prepared source and leave it visible until the journey reports its outcome.
4. Send a screenshot of the journey status/stage list with the source text out of frame, or report the status and any stage marked failed/skipped/unavailable. Do not export or upload a journey bundle; it may contain raw OCR and a captured image.

If Engine Diagnostics or Record next capture is missing, stop there and report the exact panel/title available. Do not substitute a normal capture or reset the memory store.

## Current interpretation and improvement lens

- Search should retain plausible candidates with clear confidence and evidence; suppress unsupported summaries, not the candidates themselves.
- Quality should be measured end-to-end on reviewed examples: source facts, title/description, exact/paraphrase retrieval, answer citations/refusal, and reopen usefulness. Score pipeline integrity, human usefulness, and agent grounding separately.
- EmbeddingGemma should be evaluated as an isolated contract against live MiniLM using realistic queries and concurrent capture/search resource measurements. The current vector spaces and indexes remain versioned and separate; a shared dimensionality does not make model vectors interchangeable.
- For each issue found, recommend the narrowest correction at the earliest failing stage. Do not tune a retrieval threshold to hide poor source capture, or rewrite stored memories merely to improve card wording.
