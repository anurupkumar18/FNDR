# Activity trace boundary matrix

Ticket PX-07. This document inventories every mounted `ActivityTrace` call site
and states the real process boundary behind each visible step, so a reviewer
can check that no step claims work that has not been observed. The contract
itself lives in `docs/product/activity-traces.md`; the shared vocabulary lives
in `src/shared/activity/activityTrace.ts`.

Inventory date: 2026-10-05. Method: `grep -rn "<ActivityTrace\b" src` over
non-test files. Result: **34 mounted call sites in 23 files**. The ticket lists
eight files as examples; `src/app/HomeHero.tsx` no longer mounts a trace, and
fifteen further files do.

## Reading the matrix

- **Evidence** uses the shared kinds. `frontend` is a renderer-owned
  transition (a debounce, a recorder stop, a renderer timeout). `request` is
  the moment the renderer invoked an IPC call, or the moment it returned or
  rejected; it does not claim unreported backend internals. `result` is
  metadata returned by a real call (a count, a route name, a terminal state).
  `event` is a typed native event. `snapshot` is a status value returned by a
  read.
- **Source boundary** is what starts the step. **Completion boundary** is the
  only thing allowed to move the step out of `running` or `waiting`.
- **Supersession** means a newer workflow, a newer query, or a surface leaving
  the screen replaces the trace under a new trace id, and a late result from
  the older workflow is ignored (guarded by a request counter, a trace id
  check, a cancelled flag, or an unmount flag).
- Step ids are stable within a trace. A later fact for the same id updates that
  step in place and moves it to the newest position. Traces keep at most 24
  steps.
- Frontend timers may debounce or enforce a timeout. No site advances a step
  on a timer alone, and none shows a percentage the backend did not report.
  The only percentage shown is the model download figure carried by the
  backend download status event.
- **Privacy fields allowed** is the complete list of data a step may carry.
  Every row also allows the fixed producer copy shown in the label column,
  event time, and duration.

Abbreviations used below for the privacy column: **counts** (integer tallies),
**routes** (retrieval route names such as Vector or Keyword), **model id** (a
logical model name from the catalog or a bounded `[A-Za-z0-9._-]` identifier,
never a location), **process** (a subsystem display name).

## Violations found and corrected in PX-07

1. **Search renderer timeout was labelled as a backend request boundary.**
   `src/shared/hooks/useSearch.ts` classified a timeout by sniffing the error
   message for the words "timed out". A backend error containing those words
   was reported as a client timeout, and a real client timeout was recorded as
   evidence kind `ipc-boundary` with actor "FNDR search service", although the
   backend had not answered. Fix: the renderer timer now throws a dedicated
   error class; only that class produces Search timed out, evidence
   `frontend-event`, actor "FNDR search". Any other rejection is a backend
   failure.
2. **Ask FNDR renderer timeout had the same mislabel.**
   `src/domains/ask/AskPanel.tsx` recorded its 60 second renderer timer as
   `ipc-boundary` with actor "FNDR answer service", and matched the timer by
   the exact message "timeout". Fix: a dedicated error class, evidence
   `frontend-event`, actor "Ask FNDR".

Not changed, recorded for the owner: a Screen Guide cancellation clears the
trace rather than marking the last step `cancelled` (the overlay is hidden at
that moment, and `finishScreenGuideActivity` already supports `cancelled` if a
persistent surface needs it). A cancelled macOS biometric prompt is reported as
a failed result because the native call returns `false` and gives no separate
cancellation signal. Voice has no `cancelled` event.
