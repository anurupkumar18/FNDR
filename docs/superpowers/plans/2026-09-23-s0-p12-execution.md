# S0 and P12 Execution Plan

This document breaks down two Final-epic placeholders that had no
implementation-ready work. It is intentionally narrow: reuse the current
capture loop, metrics, review worker, and MOD-04 fixture format. Do not add a
generic event framework, a second review pipeline, or an LLM-as-judge.

## Current facts

- \`capture::run_capture_loop\` is timer-driven. \`AdaptiveSampler\` already
  lowers its cadence using \`CGEventSourceSecondsSinceLastEventType\`, pauses in
  deep idle, and preserves \`forced_capture_interval\` as a 60-second fallback.
- All privacy, surface-policy, and Screen Guide race checks currently run in
  the loop before pixels. A trigger must only wake the loop. It must never
  bypass those gates or capture pixels itself.
- \`memory_review\` already queues records, uses the local inference provider,
  validates patches, preserves originals on failure, and exposes worker,
  daily, and backfill seams. What is missing is measured review quality, not
  another worker.
- \`src-tauri/tests/fixtures/gold/v0\` contains 50 extraction cases, 30
  retrieval questions, and 20 guard cases. Its labels are explicitly
  \`claude-draft\`, so they are not ground truth until a human reviews them.

## S0: event-assisted capture sampling

### Problem and goal

The active capture loop wakes on a timer even when no foreground-app change
has occurred. The first S0 slice should wake it promptly when macOS announces
an app activation while retaining the existing idle and forced-capture timer
fallbacks. It must preserve capture recall and every pre-pixel privacy gate.

### Scope and non-goals

In scope:

- App-activation notifications through the existing macOS capture boundary.
- A small typed wake reason consumed only by the capture loop.
- Counters for event wakes, fallback wakes, and coalesced notifications.
- A macOS operator check with Accessibility and Screen Recording permissions.

Out of scope:

- Global keyboard or mouse event taps, key logging, click content, or a new
  Accessibility permission requirement.
- Capturing directly from a callback, changing OCR/dedupe/storage, or removing
  the forced-capture fallback in the first slice.
- AX-text-first and ScreenCaptureKit work. Those stay in their existing
  tickets.

### Proposed behavior

\`capture/macos.rs\` owns a minimal app-activation observer. It sends a
coalesced wake signal to the already-running loop. \`run_capture_loop\` waits
for either that signal or its calculated timeout. Whichever wakes it, the
existing loop starts from its normal context read and runs all current gates.
The timer remains authoritative when the observer is unavailable or when no
activation is received.

The initial signal set is deliberately only \`AppActivated\`. A later
typing-pause decision may use the existing idle-time API, but it must not add a
global event tap without an explicit privacy review and a measured need.

### Acceptance criteria

- [ ] An activation signal causes the next normal loop evaluation without
  waiting for the full active timer interval.
- [ ] Multiple activations before an evaluation coalesce to one wake; no
  unbounded queue exists.
- [ ] Timer, idle/deep-idle, and \`forced_capture_interval\` behavior remains
  available if the observer fails or produces no signal.
- [ ] No trigger can reach pixel acquisition before existing privacy and
  Screen Guide race checks.
- [ ] The inspector exposes static-name counters for \`capture.wake.event\`,
  \`capture.wake.timer\`, and \`capture.wake.coalesced\`.
- [ ] A permissioned macOS session demonstrates an app switch followed by one
  event wake. This is operator evidence, not a unit-test claim.

### Implementation slices

#### S0-01: pure wait decision

**User-visible outcome:** no behavior change yet; the capture loop has a
testable decision boundary for a signal wake versus timer wake.

**Affected modules:** \`src-tauri/src/capture/sampling.rs\` and its unit tests.

**Work:** add the smallest enum and pure helper needed to calculate the next
wait from active, idle, and deep-idle state. Reuse \`AdaptiveSampler\`; do not
add config values in this slice.

**Acceptance:** tests cover active timer, idle timer, deep-idle no-work, and
an already-pending activation. The test proves the helper's output only.

**Verify:** \`cd src-tauri && cargo test capture::sampling\`.

#### S0-02: macOS activation source and loop integration

**User-visible outcome:** switching foreground apps wakes the existing loop
promptly, while the timer remains the fallback.

**Affected modules:** \`src-tauri/src/capture/macos.rs\`,
\`src-tauri/src/capture/mod.rs\`, \`src-tauri/src/capture/sampling.rs\`, and
focused tests.

**Work:** create one bounded channel at capture startup, register a
foreground-app activation observer in the macOS module, and select the
channel or timer inside the current loop. The sender uses non-blocking
coalescing. Observer setup failure logs once and leaves timer sampling intact.
Do not expose this channel outside \`capture\`.

**Acceptance:** a fake source proves event and timer wakes use the same normal
evaluation entry point; observer-init failure uses timer fallback; a full
channel increments \`capture.wake.coalesced\` rather than blocking.

**Verify:** \`cd src-tauri && cargo test capture::sampling\` and
\`cd src-tauri && cargo test capture::\`.

#### S0-03: instrument and prove the first slice

**User-visible outcome:** the Pipeline Inspector can distinguish why the loop
woke and an operator can confirm the signal on this Mac.

**Affected modules:** existing \`telemetry/runtime_metrics.rs\`, Pipeline
Inspector presentation only if it already renders arbitrary counters, and
\`docs/evidence/W05/\`.

**Work:** use existing \`runtime_metrics::bump\` calls only. Capture a short
permissioned session that includes an app switch and an idle period; record
counter values and whether Screen Recording/Accessibility were granted.

**Acceptance:** evidence names the build/commit, session duration, observed
counter values, and any unavailable permission. It does not claim CPU savings
without a baseline comparison.

**Verify:** focused Rust tests plus the existing metrics dump command. Human
permission and live-capture checks remain manual.

### Risks and rollback

The primary risk is a notification source that is unavailable in the Tauri
runtime or emits a burst. S0-02 contains it behind the existing timer path,
uses a one-slot coalescing channel, and can be rolled back by not starting the
observer. The product contract in ADR-004 remains unchanged: a wake signal is
not a pixel capture.

## P12: post-capture review scoring

### Problem and goal

The review pipeline can reject ungrounded or meta-narrated patches, but it has
no outcome-quality measurement. P12 should produce a deterministic report of
whether reviewed output is grounded, useful, and safer than the original on a
human-reviewed fixture set. It must not fabricate labels or make a model judge
its own prose.

### Scope and non-goals

In scope:

- A versioned review-evaluation JSONL format adjacent to MOD-04's fixtures.
- Deterministic scoring for human-supplied expected facts, forbidden facts,
  activity type, and lifecycle outcome.
- A report that separately states structural safety, acceptance/rejection, and
  quality results.
- A small runner that can consume saved local-review outputs without sending
  data anywhere.

Out of scope:

- Treating \`claude-draft\` labels as verified gold, using an LLM judge,
  retraining or changing prompts, or changing production review behavior.
- Checking real user captures into git. Inputs remain synthetic/public.

### Evaluation contract

Each review case has \`id\`, \`evidence\`, \`before\`, \`reviewed\`, and
\`expected\`. \`expected\` contains the reviewed \`activity_type\`, required
evidence terms, forbidden terms, and a human decision of \`improves\`,
\`preserves\`, or \`rejects\`. Metadata includes \`labeler\`, \`reviewed_by\`,
and \`label_status\`. The runner must refuse to print a quality score unless
every selected case is \`label_status: human_reviewed\`; it may still print
structural safety counts for drafts.

The score is intentionally deterministic:

- Required-term recall: fraction of expected evidence terms in reviewed text.
- Forbidden-term violations: count of forbidden terms present in reviewed
  text.
- Activity accuracy: exact match to the reviewed label.
- Unsafe review rate: reviewed outputs that fail grounding/narration checks or
  violate a forbidden term.
- Improvement rate: human \`improves\` cases whose reviewed output passes the
  required/forbidden checks. This is reported only for human-reviewed labels.

The report also includes worker outcomes (\`reviewed_local\`, \`reviewed_daily\`,
\`review_failed\`, skipped, provider error), queue deferrals, and latency from
existing metrics. It never conflates a validator rejection with a low-quality
but accepted patch.

### Acceptance criteria

- [ ] A fixture parser rejects missing fields, invalid lifecycle outcomes, or
  an unknown \`label_status\`.
- [ ] Draft fixtures produce only structural counts and a clear
  \`quality_score_available: false\` status.
- [ ] Human-reviewed fixtures produce the five deterministic metrics above,
  split by dev/test/guard.
- [ ] Guard cases cannot be used in a tuning run; the CLI requires an
  explicit report-only guard flag.
- [ ] The evaluator has fixture tests for a passing patch, forbidden-term
  hallucination, missing required fact, and a validator-rejected patch.
- [ ] The evidence report identifies fixture version, commit, local model
  version, case counts, and label-review status.

### Implementation slices

#### P12-01: review fixture contract and evaluator

**User-visible outcome:** FNDR can score saved review output reproducibly,
without changing the worker.

**Affected modules:** \`src-tauri/tests/fixtures/gold/v0/\`, a small evaluator
under \`scripts/eval/\`, and its focused tests.

**Work:** add the JSONL schema/readme and three synthetic evaluator fixtures.
Implement parsing and deterministic score calculation in the existing
evaluation-script style. The evaluator consumes JSONL only and has no model or
database dependency.

**Acceptance:** the four evaluator fixtures above pass; draft status suppresses
quality claims; malformed input fails with a named case id.

**Verify:** focused evaluator test command and a draft-fixture run. Do not run
the full application suite for this documentation/data-only slice.

#### P12-02: local review replay adapter

**User-visible outcome:** a developer can save local review outputs from a
synthetic fixture run in the evaluator's format.

**Affected modules:** \`memory_review::pipeline\` test seam or a test-only
adapter, never the production worker scheduling path.

**Work:** reuse \`ReviewProvider\` with a fixture provider and serialize each
\`MemoryReviewOutcome\` plus output fields. Keep review execution local and make
the adapter opt-in. Do not turn a test fixture into a production IPC command.

**Acceptance:** the adapter preserves the original record, reviewed patch, and
rejection reason sufficiently for P12-01 to score; no real capture or user
store is read.

**Verify:** \`cd src-tauri && cargo test memory_review\` plus the P12 evaluator
on its generated synthetic output.

#### P12-03: human label pass and baseline report

**User-visible outcome:** the team has a first honest quality baseline for the
local reviewer.

**Dependency:** a human must review MOD-04 labels and label the review cases.
This cannot be completed by an agent without fabricating ground truth.

**Work:** independently label at least ten cases blind, calculate agreement,
mark accepted cases \`human_reviewed\`, then run the held test set once. Record
guard results only after the prompt/model is frozen.

**Acceptance:** the evidence report states exact label counts, agreement,
model/configuration, all five metrics, and any missing labels. It does not
claim a quality result when human review is incomplete.

**Verify:** evaluator run on the locked test split and a separate explicit
guard report.

### Risks and rollback

The risk is treating simple term checks as semantic truth. The report labels
them deterministic proxy metrics and keeps the human decision as the quality
authority. P12 can be rolled back by deleting only its offline fixtures and
scripts; it changes neither stored memories nor the review worker.

## Recommended order

1. S0-01 and P12-01 can proceed independently and are each one focused
   session.
2. S0-02 follows S0-01 because it changes runtime scheduling.
3. P12-02 follows P12-01 because it must emit the locked schema.
4. S0-03 needs local macOS permissions; P12-03 needs a human label pass.

## Architecture and anti-bloat review

- No new cross-domain service: S0 stays in \`capture\`, P12 stays offline next
  to the existing gold fixtures.
- No new production configuration until S0 has measured event wake behavior.
- No duplicated validator: P12 reports the existing review outcome and uses
  \`memory_review\` validation rather than reimplementing grounding rules.
- No ADR change is required before S0-01 or P12-01. Before S0-02 lands,
  update ADR-005 with the observer, fallback, and explicit no-input-tap
  decision because it changes capture scheduling.
